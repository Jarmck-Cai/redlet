# Topic Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add explicit user-selected topic tags to the existing checked publishing workflow.

**Architecture:** Optional normalized tags travel with the current bundle. A focused topic module handles native editor associations and body readback; preview passes observed IDs explicitly to final submission checks. Empty tags preserve legacy fingerprints.

**Tech Stack:** Existing TypeScript, Playwright, node:test; no new dependencies.

**Spec:** ../specs/2026-10-28-topics-design.md

## Global Constraints

- schema_version remains1; old bundles and journals continue to work.
- At most10 distinct tags; original body plus visible tag suffix fits1000 Unicode characters.
- Recommendations remain assistant proposals until user selects the tags.
- Existing account, image, settings and once-only protections remain.
- No dashboard, scheduling, model integration or new public posts.

## Review Focus

- A late suggestion for another query must not be selected.
- A similarly named or duplicated exact candidate must not be accepted.
- Plain #text or malformed native metadata must not pass association checks.
- Topic ID/name/order changes after preview must block the final click.
- Empty tags must preserve legacy task hashes and trailing blank paragraphs.

# Redlet 话题标签

2026-10-28。用户已批准：支持给定话题，也可由助手根据正文推荐、用户选定；沿用当前发布流程，正确添加和核对，做好测试。看板、定时发布、初始化及入口验收不在本轮范围。

## 约定

- 素材包 schema_version 保持1，新增可选 `tags: string[]`。省略或空数组保持旧行为与旧任务指纹。
- 标签去首尾空白及一个前导#，按完整名称去重并保留顺序；空名称、内嵌#、换行/控制字符拒绝。本版工具最多支持10个不同话题，这是工具范围，不宣称平台规则。
- 正文原字节归一规则、段落和末尾空行保持。在正文之后新增一个段落，按给定顺序输入#话题并选择精确名称的候选。包含话题可见文本的最终长度也受现有1000字符工具限制。
- 推荐由当前协作助手基于本篇正文提出，用户选定后保存到tags；本轮不引入模型配置、付费接口或隐式推荐发布。
- 真实Rednote观察：候选位于 `#creator-editor-topic-container .item .name`，其父组件text反映当前#查询；选中后生成 `a.tiptap-topic[data-topic][contenteditable=false]`，JSON含真实id/name，显示含隐藏的`[话题]#`标记。新建话题选项最终也生成正常id。
- 仅接受一个精确名称候选，等待当前查询对应的结果；相似候选、重复精确候选、无候选或无法生成有效关联节点均停止并指出标签。不自动选第一项或把普通#文字当成功。
- 预览回读核对原正文、话题名称/顺序/节点及ID。提交前两次回读还需与该次预览记录的ID相符；话题进入素材指纹和本地回执。
- 原有账号、图片、可见性、AI声明与一次提交保护保持。原.runtime留在原处，真实测试仅预览公开示例，不提交笔记。

## 验收

输入规范化和总长度；旧稿/旧指纹兼容；真实Chrome受控候选交互、精确匹配与异步候选、原正文/空行保持、普通文本拒绝、话题丢失/换名/换ID/换序阻止提交；完整测试、类型检查、构建及构建后带话题样例check；实际平台普通示例preview且submitted:false。
